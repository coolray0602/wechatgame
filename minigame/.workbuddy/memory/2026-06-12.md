# 2026-06-12 工作記錄

## 調整頂部 UI 水平排版

- **問題**：已得分數、剩餘卡牌、現在關卡、設置按鈕原本垂直疊放在標題下方，造成頂部區域空間浪費且不美觀。
- **修改文件**：`game.js`
- **修改內容**：
  1. 第一版（水平單排）→ 空間不夠用，已廢棄
  2. 第二版（右半部垂直排列，靠右）：
     - 右側區塊整體垂直置中於頂部區域
     - 第一行：**[分數框] [⚙️]**（同行，靠右）
     - 第二行：**剩餘 N 張**（右對齊）
     - 第三行：**第 N / N 關**（右對齊）
     - 剩餘/關卡文字改用 `textAlign = 'right'`，背景框從右往左計算
     - 不再需要空間保護邏輯（右半部垂直疊放本來就不會超出標題範圍）
  3. 修正靠右失敗問題（第三版）：
     - 根因：`menuButtonInfo?.left` 在部分裝置可能返回異常值（0 或很小），導致 `rightEdge` 計算偏左
     - 修正：加入 `capsuleValid` 合法性判斷（capsuleLeft > 40% 螢幕寬 且膠囊寬度 > 30px），不合法時 fallback 到 `screenWidth - uiMargin`
     - 加入 console.log 輸出膠囊原始值便於 debug
  4. 修正標題太小、分數欄位與膠囊重疊問題（第四版）：
     - 根因：`topContentBottom = Math.min(topAreaBottom, menuButtonBottom)` 把整個頂部垂直空間壓縮到膠囊底部以下（iPhone 上 contentH 可能只剩 ~40px）
     - 修正：`topContentBottom = topAreaBottom`（膠囊僅佔右側水平，不應限制整體垂直空間）
     - 標題高度從 85%/70% 調為 78%/68%
     - 還原 `rightEdge` 的膠囊水平避讓邏輯（第三版曾被簡化掉）
     - 移除不再需要的 `menuButtonLeft` / `menuButtonBottom` 變數
  5. 右側元件放到膠囊下方而非左側（第五版）：
     - 原因：直屏手機右側水平空間有限，放膠囊左邊太擠
     - 修正：`rightBlockTop = capsuleBottom + gap`（從膠囊底部下方開始）
     - `rightEdge = screenWidth - uiMargin`（下方無水平衝突，可用全寬）
     - 標題仍垂直置中於完整 TOP_AREA（左側獨立不影響）
     - 移除 `topCenterY` 不需要的變數
  6. 字體加大、簡化關卡顯示、移除關卡選擇（第六版）：
     - `INFO_FONT_SIZE` 從 11~13 調整為 14~16（放大）
     - 渲染時 `infoFontSize` 下限從 11 調為 14
     - `tagH` 渲染從 `*1.55` 調為 `*1.6`，`tagPadX` 從 `*0.55` 調為 `*0.6`
     - 關卡文字從 `第 N / 10 關` 改為 `第 N 關`
     - 設定面板移除關卡選擇按鈕和「切換關卡」標籤，面板高度從 360→240
     - 設定面板三個按鈕的垂直位置重新調整
     - `resetGame()` 強制回到第 1 關
  7. 字體再加大、遊戲結束增加再來一次按鈕（第七版）：
     - `INFO_FONT_SIZE` 從 14~16 調整為 16~18（再次放大）
     - `infoFontSize` 渲染下限從 14 調為 16
     - 遊戲結束畫面：新增「再來一次」按鈕（金黃色圓角）
     - 按鈕下方顯示楷書激勵文字「我就不信過不了！」
     - 新增 `gameOverBtnRect` 全域變數 + 觸摸事件處理
  8. 移除文字背景、四元件垂直對齊標題（第八版）：
     - 移除剩餘卡牌和關卡文字的圓角背景標籤，改為純文字

     - 右側四元件（分數框、設定鍵、剩餘文字、關卡文字）整體垂直置中於標題高度（`topCenterY`）
     - 修復 `rightBlockTop` 使用時尚未定義 `rightBlockH` 的 bug
